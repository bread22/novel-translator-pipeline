# 上传去重

`POST /api/v1/books/upload` 在原有书籍 ID 检查之外增加两层内容检查：

1. **原文件 SHA-256**：按字节比较已保存的原文件，文件重命名或 ID 规则变化不影响判重。命中时在注册前返回 HTTP 409。
2. **正文 SHA-256**：使用导入解析器生成的 manifest 原文段落，按阅读顺序计算指纹；在上传事务内完成比较，命中则回滚注册，不重置旧工作区、不返回导入成功。封面、OPF 元数据或 ZIP 压缩变化不影响相同正文的匹配。

两层检查都命中任一本已有书籍就停止导入。HTTP 409 的 `detail` 对象包含：

```json
{
  "code": "DUPLICATE_BOOK",
  "detail": "书籍已存在：existing-id（正文指纹相同）；已跳过导入，保留已有译文",
  "existing_book_id": "existing-id",
  "matched_by": "body_sha256"
}
```

原文件命中时 `matched_by` 为 `source_sha256`。前端现有批量上传流程仅将成功导入的书籍加入队列，因此重复项不会自动入队。

## 正文规范化 v1

算法标识：`original-paragraphs-nfc-v1`。

- 只使用 `chapters[].paragraphs[].source`，不使用译文、书名、作者、ID、文件路径或生成的章节标题。
- 跳过标为 `cover` / `toc` 的章节；其余章节保留原有顺序。
- Unicode NFC 规范化，将段落内连续空白统一为一个空格，并清除首尾空白。
- 保留文字、标点、大小写、章节边界和段落边界；不做 NFKC、简繁转换或模糊匹配。
- 忽略空段落、空章节。空正文不生成正文指纹，防止图片书/空书彼此误判。
- 将版本标识及章节/段落数组序列化为确定的 JSON，再计算 SHA-256。

这是一种保守的精确去重：正文修改、段落重组、章节拆分方式改变，可能产生不同指纹。它不是“同一作品”的语义识别；正文完全相同的版本会被视为重复，即使元数据不同。

## 历史数据与持久化

新导入书籍将 `source_sha256`、`body_sha256`、`body_version` 保存到书籍数据目录中的 `upload-fingerprints.json`。

历史书籍无需先迁移：上传扫描到该书时，首次计算后会原子补写 `upload-fingerprints.json`（即使本次上传随后因重复返回 409，也保留缓存）。从 `source.epub` / `source.txt` 或工作区的原始 EPUB 计算文件 hash，从 manifest 原文计算正文指纹，不修改已有 manifest、译文或进度。缓存额外记录 `manifest_stat` 和 `source_stat`（路径、大小、mtime、ctime、inode、设备）。后续检查输入状态和算法版本，未变化时直接复用持久化 hash，服务重启后仍有效；未变化的缓存不重复写入。原文件变化只重算文件 hash，manifest 变化重算正文指纹（包括仅译文变化时的保守重新校验），版本变化则全部重算。计算前后会检查输入状态，避免并发更新导致错误缓存。扫描范围为当前书库，成本随书籍数增长。

缓存缺失、旧格式或损坏时自动重建；缓存写入失败会记录警告，仍以本次算出的结果判重，不会因此放行重复书籍。补写只针对本次实际扫描到的书籍，不是启动时全库迁移；同 ID 的提前拦截不触发内容指纹计算。

如果原文件缺失，仍可用 manifest 原文判重；存在有效历史指纹记录且正文一致时，也可以保留文件 hash 匹配能力。若既没有原文件/有效文件 hash，也没有可匹配的原文，则只能依赖 ID 检查。不会拿导出的译文 EPUB 当作原文件。

## 替换、并发与回滚

- 同 ID 的显式 `replace=true` 仍可替换本书。
- `replace=true` 不绕过其他 ID 的内容冲突；避免将同一正文导入两个 ID。
- 上传检查与发布共用书库级锁，防止不同 ID 并发上传同一内容时双双通过。支持 flock 的平台同时覆盖多个服务进程；其他平台使用进程内锁。
- 保留现有的每书维护预约与备份恢复。正文冲突或指纹保存失败会回滚书籍数据和工作区。
- 该锁约束此 Web 上传入口；直接调用底层 CLI 导入不经过此检查。
- 本改动不取消已经入队的重复任务，不删除历史重复记录，也不会自动重启正在运行的服务。
