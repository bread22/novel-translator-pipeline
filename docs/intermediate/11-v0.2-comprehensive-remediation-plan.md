## 1. 计划目标

本计划覆盖 v0.2 全面审阅中记录的全部缺陷与改进项，并按可验证、可回滚、可阶段性交付的批次推进。

总体目标：

1. **先止血**：关闭密钥泄露、路径逃逸、配置损坏和残缺前端交付等发布阻断项。
2. **再收敛执行模型**：统一 TaskManager 与 QueueManager，建立单书单任务、严格状态机和可靠取消语义。
3. **修复数据正确性**：统一审阅 Schema、分块记忆合并、Fallback 处理和 Glossary 字段契约。
4. **提升前端可靠性**：修复 SSE、请求竞态、错误展示、超时、可访问性和重复实现。
5. **建立交付闭环**：干净安装、构建、启动、测试、发布版本与文档全部可重复验证。

### 1.1 完成定义

全部批次完成后应同时满足：

- 全新 clone 可按 README 构建并打开完整 Web Studio；
- 生产静态资源中的每个引用文件都存在于交付物；
- API 响应不包含明文密钥或完整 `.env`；
- 同一本书任一时刻最多存在一个活动执行任务；
- pause、resume、cancel、restart recovery 具有确定状态和回归测试；
- Schema-valid 的 Glossary/Memory 数据经分块、双审、API 和前端往返后不丢字段；
- Fallback #1 抛异常或部分成功时仍会正确推进到后续 Provider；
- Python 支持范围与 CI 矩阵一致；
- 后端、前端、E2E、构建和安全回归全部通过；
- `pyproject.toml`、前端包、OpenAPI、health、CHANGELOG 和 Git tag 使用同一版本。


- 将可复用逻辑迁入 JobManager；
- 路由不再接触 `_lock`、`_items`、`_save_state`；
- 公共 API 自身处理锁，禁止锁内调用另一公共方法。
- 所有调用迁移完成后删除 QueueManager；不保留旧类名、旧模块导出或适配层。

### 6.3 状态机

统一状态：

```text
pending -> running -> completed
                   -> failed
                   -> cancelling -> cancelled
          running -> pausing -> paused -> running
pending -> cancelled
failed/cancelled -> pending (retry)
```

规则：

- `paused` 仍占用 worker slot，除非 worker 已安全释放资源；
- cancelled/failed/completed 为终态，普通 worker 更新不得覆盖；
- 状态转换集中在 `transition(item_id, expected, target)`；
- completed 前必须确认 cancellation token 未设置；
- finalize 前再次检查 token；
- `max_cycles` 在统一 worker 中生效；
- 同书已有 active job 时返回现有 job 或 409，不再创建第二任务。

### 6.4 取消与暂停粒度

#### [MODIFY] `translator/pipeline/chapter_pipeline.py`

- 接受 `CancellationToken` 和 `PauseGate`；
- 在以下边界检查：
  - 每个翻译 batch 前后；
  - 每次 fallback 前；
  - 审阅前后；
  - 修复写回前；
  - finalize 前及复制前；
- Provider/CLI 调用支持超时和子进程终止；
- 暂停时保留可恢复 checkpoint。

### 6.5 删除与重置协议

`books.py` 的 delete/reset 顺序改为：

1. 获取 book operation lock；
2. 请求取消活动任务；
3. 等待 worker 在限定时间内确认停止；
4. 生成删除或重置事务日志；
5. 执行文件操作；
6. 更新任务历史；
7. 广播最终事件。

超时后保留任务和文件，不进入半删除状态。

### 6.6 持久化和恢复

- queue state 增加 `schema_version`；
- JSON 状态写入继续使用原子替换；
- 服务启动时：
  - running/cancelling/pausing 转为 recovery_pending；
  - `is_paused=false` 时自动 dispatch；
  - `is_paused=true` 时保持 pending；
- 记录最后 checkpoint、进程启动 ID 和恢复原因；
- 历史记录按数量/日期裁剪。

### 6.7 测试矩阵

- stop route 无锁重入；
- 最后一章中途 cancel 后不执行 finalize；
- paused job 不触发额外并发；
- 同书从 queue 和 tasks 同时启动只产生一个 worker；
- delete/reset 等待 worker 退出；
- restart 自动恢复 dispatch；
- max_cycles=0/1/N 行为与 CLI 一致；
- stop_on_error 在并发任务下行为确定；
- 100 次并发 enqueue/cancel/retry 不损坏 state 文件。

### 6.8 迁移和回滚

- JobManager 使用独立的新状态文件和新 schema，不读取旧 `queue_state.json`；
- 切换前只备份旧状态文件，回滚时由旧版本继续读取该备份；
- 单个合并批次内迁移全部路由、CLI 和测试，随后删除两个旧 manager；
- 验收要求代码库中不存在对 TaskManager、QueueManager 及其旧私有字段的运行时引用。

## 16. 已采用的架构与交付决策

1. **前端交付**：源码仓库按需构建 frontend，发布归档包含已验证的完整 `frontend/dist`；
2. **上游依赖**：采用显式 external runtime，通过 `NOVEL_TRANSLATOR_ROOT` 和 `NOVEL_TRANSLATOR_PYTHON` 配置；CI 使用等价 fixture 验证契约；
3. **任务引擎**：以 `JobManager` 取代旧执行引擎，Web 与批处理共享同一状态机和持久化模型；
4. **认证方式**：默认仅监听 loopback，非 loopback 部署要求管理 token；
5. **SSE 历史**：本版本只保证页面会话内的事件保留，不宣称后端持久事件日志；
6. **Python 支持**：本轮固定为 3.10–3.13，3.14 及后续版本另行评估；
7. **版本策略**：代码和发布材料统一为 0.3.0，但 tag、GitHub Release 与产物发布暂缓。
